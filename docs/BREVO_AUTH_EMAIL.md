# Supabase OTP delivery through Brevo

The app continues to use Supabase Auth for signup, confirmation, recovery,
OTP generation, expiry and verification. Brevo only delivers the signed email
payload; it never generates or verifies the OTP.

## Deploy the hook

From the repository root, link the correct Supabase project and deploy the
existing hook:

```sh
supabase link --project-ref oamqpmqlydxmxeeipyha
supabase functions deploy send-auth-email --no-verify-jwt
supabase secrets set --env-file supabase/functions/send-auth-email/.env
```

The `.env` file is ignored and must never be committed. Required server-only
values are:

```text
BREVO_API_KEY=<Brevo API key>
BREVO_SENDER_EMAIL=developer.fluxtonx@gmail.com
BREVO_SENDER_NAME=United Union Health
EHEALTH_SUPPORT_EMAIL=developer.fluxtonx@gmail.com
SEND_EMAIL_HOOK_SECRET=<secret generated by Supabase Auth Hooks>
AUTH_EMAIL_OTP_EXPIRY_SECONDS=3600
AUTH_EMAIL_OTP_LENGTH=6
AUTH_RECOVERY_MODE=otp
```

Verify `developer.fluxtonx@gmail.com` in Brevo before using it as the sender.

## Enable the Supabase hook

In Supabase Dashboard → Authentication → Hooks:

1. Create a **Send Email** hook.
2. Choose HTTPS and use
   `https://oamqpmqlydxmxeeipyha.supabase.co/functions/v1/send-auth-email`.
3. Generate the signing secret.
4. Save the exact generated secret as `SEND_EMAIL_HOOK_SECRET` in the
   Edge Function secrets, then save the hook.

Keep Email enabled, Confirm email enabled, OTP length 6 and OTP expiry 3600
seconds. After the hook is enabled, Supabase Auth still owns the OTP flow and
the Flutter app verifies it with `verifyOTP`.

Do not put `BREVO_API_KEY` or `SEND_EMAIL_HOOK_SECRET` in Flutter,
`supabase/setup.sql`, or any public configuration file.
